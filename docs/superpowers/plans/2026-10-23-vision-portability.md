# 识别链路统计、模型适配与餐图验收实施计划

用户已确认第 1–3 项，后端为主、不发布小程序、不改现有客户端协议。

1. 复用现有阶段 observe，Worker 将其发至受签名保护的诊断入口；区分 provider/营养补全/评价/持久化及整体 Worker，统计脚本分开提交/轮询/最终任务，按模型输出 P50/P95、成功率、备用触发率。无数据返回 null，不把 202 当识别成功。
2. metadata.vision 定义图片输入偏好、思考参数能力、JSON 格式能力；独立视觉请求适配器处理请求参数与预算，旧 DeepSeek/Qwen 配置保持行为。路由继续负责凭证、配额与主备，输出继续经过现有食物结果校验。未知协议明确失败；不同协议注册专用适配器，不假装兼容。
3. 固定、具有 SHA256 的餐图清单覆盖普通餐/便当/火锅/海鲜/多餐盘，标注可见食物与排除项。可重复的验收 runner 走同一视觉适配代码并记录时延、schema、漏识别/误识别候选；人工审核份量与难辨食物。不使用生成图冒充准确性真值。
4. 测试先于实现，完整后端回归；DEV/PROD 代码更新后下载比对；两分支同步推送。保持现有主模型和备用绑定。真实验收若认证失效或样本不足，明确标记，不伪造通过。
