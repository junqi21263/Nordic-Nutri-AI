# 模型额度管理设计

## 目标

在 DEV 管理后台中把模型调用统计、内部执行限额和厂商额度来源分开呈现，并让内部模型级策略可被安全编辑和真实执行。

## 数据与安全边界

- 新表 `ai_model_quota_policies` 以 `(provider_key, model_key, feature_key)` 唯一，保存 `daily_request_limit`、`alert_threshold_percent`、`enabled`、`provider_balance_mode`、`provider_balance_manual` 与更新时间。
- 私有表 `private.ai_model_quota_windows` 以同一三元组和 UTC 日窗口保存全局计数；安全定义的 RPC 在一次数据库操作中检查并递增，不能复用按用户的限流窗口。
- 表只允许云函数服务端访问；后台继续通过管理员会话调用 `/api/admin/*`。
- API Key/Token 不写入策略表、不回传前端、不写审计详情。
- 厂商余额模式为 `unsupported`、`manual` 或 `automatic`。首期只有手工值会显示数值；没有受验证的厂商 API 读取能力时不得展示伪造余额。

## 执行链路

1. 路由解析出厂商、模型和功能。
2. 云函数在发出提供商请求前读取该三元组策略；`enabled=false` 时拒绝调用，超过 `daily_request_limit` 时由原子 RPC 拒绝。
3. 计数在实际发出提供商请求前保留（提供商即使失败也可能产生费用）；图片预处理、鉴权等提供商调用前失败不会计数。失败与限流继续进入现有 Ops 观测。
4. `/ops/quota` 合并运行时路由、策略、系统指标；前端显示当前用量/限额、告警状态和余额来源。

## 后台交互

- 额度表每行显示功能、厂商、模型、今日使用、内部限额、状态和厂商额度来源。
- “编辑策略”抽屉允许更新每日上限、告警阈值、启停和手工余额；保存后刷新行状态。
- 无厂商余额接口时稳定显示“未接入”，不会将 Token 或系统用量误作余额。
- 历史趋势和模型详情以厂商 + 模型为唯一标识。

## 验收

- 同名但不同厂商模型的统计和策略互不影响。
- 禁用或触发模型级日限额时，调用在提供商请求前被拒绝。
- 管理接口不返回凭证或完整环境变量。
- 页面能显示策略、来源、告警和刷新状态；无真实厂商余额时不显示虚构数值。
