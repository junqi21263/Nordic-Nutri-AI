# Android 登录态自动续期与应用升级设计

## 目标

- Android 用户正常使用期间保持登录，连续 30 天未使用后才需要重新登录。
- 旧版本仍能进入主页；支持应用市场升级，并为测试包、侧载包提供站内 APK 升级兜底。
- 复用现有 CloudBase HTTP 函数、PostgreSQL、Android 加密存储和页面风格，不建立第二套认证或发布系统。

## 登录态自动续期

### 会话模型

- 访问令牌保持现有 7 天有效期。
- 登录或注册成功时同时签发 30 天有效的刷新令牌。
- 刷新令牌使用高熵随机值；数据库仅保存哈希，不保存明文。
- 每次刷新成功都轮换刷新令牌，并将有效期从本次使用时间顺延 30 天。
- 改密、账号注销、退出登录或用户 `token_version` 变化时，相关刷新会话失效。
- 支持同一账号多设备登录，每个设备保存独立刷新会话。

### 客户端流程

现有加密存储继续保存完整会话。应用启动或 API 请求遇到明确的 401 时，只允许一个刷新请求在途：

1. 调用 `/auth/refresh`。
2. 成功后原子替换访问令牌与刷新令牌。
3. 自动重试原请求一次。
4. 网络错误或服务暂不可用时保留本地会话并提示重试，不跳转登录页。
5. 只有刷新令牌确定无效、过期或被撤销时，才清空会话并进入登录页。

不无限重试，不在日志中输出任何令牌。

### 后端与数据

新增最小刷新会话表，记录用户、令牌哈希、过期时间、撤销时间和轮换关系。所有读写均在后端服务身份下完成，不向客户端直接开放。

新增：

- `POST /auth/refresh`
- `POST /auth/logout`，用于撤销当前刷新会话

现有登录和注册响应增加 `refreshToken`，保留原字段兼容当前调用方。

## 应用升级

### 发布数据

新增最小应用版本表，保存：

- 平台与发布渠道
- `versionCode`、`versionName`
- APK 的 CloudBase Storage 下载地址与 SHA-256
- 更新说明
- 应用市场链接
- 是否启用

新增公开只读 `GET /app/version?platform=android&channel=...`。接口只返回已启用版本，不泄露管理凭据。

### 检测时机

- 用户成功进入主页后后台检查一次，不阻断启动和登录。
- 同一次应用进程不重复检查。
- 普通更新允许稍后提醒；本期不实现强制更新。
- 旧版本没有检测代码时保持原行为，因此仍能进入主页。

### 升级路径

Android 原生桥提供当前版本、安装来源、打开应用市场、下载和安装 APK 的能力。

1. 从应用市场安装且存在可处理的市场链接时，优先打开应用市场详情页。
2. 测试包、侧载包或应用市场不可用时，允许选择站内更新。
3. 站内更新下载到应用私有缓存，严格校验 SHA-256。
4. 校验成功后通过现有 `FileProvider` 调起 Android 系统安装确认页。
5. 哈希不一致、下载失败或安装权限不足时停止安装，并给出可恢复提示。

应用自身不静默安装，也不绕过 Android 系统授权。

### 前端交互

新增一个符合现有 Nordic 主题的更新弹窗：版本号、更新说明、首选升级按钮、站内升级兜底和“稍后提醒”。下载期间显示确定进度并防止重复触发；页面销毁时解除监听。

## 兼容与错误处理

- 新客户端可以读取只有访问令牌的旧会话；访问令牌仍有效时继续使用。
- 旧会话访问令牌过期且没有刷新令牌时，仍需登录一次，之后进入自动续期机制。
- 认证刷新与版本检查相互独立；版本服务失败不能影响主页。
- DEV 和生产使用各自的会话密钥、数据库记录、版本配置和 APK 地址，不跨环境续期。

## 测试与验收

- 后端：签发、哈希存储、轮换、过期、撤销、改密失效、并发复用拒绝、跨用户隔离。
- 前端：单次刷新并发去重、请求只重放一次、网络错误不清会话、确定无效才退出。
- 更新：版本比较、同版本不弹窗、市场优先、市场不可用回退、下载失败、哈希错误禁止安装。
- 构建：现有 TypeScript、测试、Android H5、Capacitor 同步和 Gradle APK 构建。
- 真机：登录后重启恢复、模拟过期后自动续期、主页更新提示、市场跳转、APK 覆盖安装及数据保留。

生产部署、生产数据库迁移和应用市场发布不在本次默认执行范围；先在测试环境完成部署和真机验收。
