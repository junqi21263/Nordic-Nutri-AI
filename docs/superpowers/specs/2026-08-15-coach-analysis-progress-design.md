# NOVA 教练分析进度设计

在不修改 `delta / complete / error` 流协议的前提下，当前一轮 assistant placeholder 在发送后立刻进入 `analyzing`，并在首个有效回答 chunk 到达时完成、记录耗时、自动折叠和进入 `answering`。分析摘要是用户可见的状态说明，不是模型内部推理。

消息的可选 `analysis` 元数据只存在于本次客户端生成生命周期：它包含开始/结束时间、展开状态、`frontend-summary` 来源和安全摘要步骤。历史服务端消息不补造该数据。服务端最终消息替换 placeholder 时会带入完成的 `analysis`，避免闪烁。

当问题明确关联今日摄入或个人营养目标时，使用“查看今日饮食记录 / 整理当前营养摄入 / 生成饮食建议”；其他问题仅使用“理解你的问题 / 整理相关营养信息 / 生成建议”。不宣称读取体重趋势、训练数据或其他没有请求的数据。

流请求提供取消接口。页面卸载会终止流且拒绝后续回调；流式失败时保留分析摘要进入既有非流式回退，成功后完成同一消息；最终失败继续既有错误反馈并移除临时消息。
