# 扫描保存后的详情返回与分析退出弹窗

## 目标

修正两个彼此独立的交互问题：

1. 扫描分析结果保存后进入餐食详情，再点击详情页返回时回到“饮食记录”页，而不是回到已完成的扫描分析页。
2. 扫描分析页点击顶部返回后，确认弹窗在视口内水平、垂直居中并固定显示，弹窗打开期间页面不可上下滚动，两个按钮文案保持单行。

## 当前根因

- 保存成功后的共享 `PageLayout` 会通过 `Taro.navigateTo` 打开餐食详情。
- 餐食详情顶部返回无条件调用 `Taro.navigateBack`，因此扫描入口的历史栈仍会暴露分析结果页。
- `ConfirmDialog` 使用的 `.modal-backdrop` 当前采用底部对齐；分析结果页没有在弹窗打开时锁定页面滚动。

## 方案

### 扫描来源返回

共享“查看本餐”跳转只在当前页面为扫描分析页时，为详情 URL 增加 `from=analysis` 来源参数。餐食详情读取该参数：

- `from=analysis`：顶部返回使用 `Taro.switchTab({ url: "/pages/meal-records/index" })`；
- 其他来源：保持现有 `Taro.navigateBack()`。

这样不会改变手动记录、记录列表或其他详情入口的返回语义，也不需要全局来源 store。

### 分析退出弹窗

- 分析结果页将 `exitConfirmOpen` 传给 `PageLayout` 的 `scrollLocked`。
- 仅对 `.page-layout--analysis-result` 作用域覆盖 modal backdrop 的对齐方式为居中，并阻止触摸滚动。
- 确认弹窗按钮保持现有布局与文案，只增加单行约束，避免“放弃并返回”等文字换行。

## 不在范围内

- 不修改保存 API、餐食数据、扫描识别链路或成就/里程碑语义。
- 不修改其他页面的 `ConfirmDialog` 位置。
- 不重构导航工具、全局状态或页面布局架构。

## 验收

- 扫描分析保存 → 查看本餐 → 详情页返回：进入饮食记录页。
- 手动记录保存 → 查看本餐 → 详情页返回：仍按原有 `navigateBack` 逻辑。
- 分析页打开退出弹窗：弹窗位于视口中心，页面内容不随上下滑动，背景固定。
- “继续分析”“放弃并返回”均保持单行。
- 现有分析、餐食详情和全量小程序测试继续通过。
