# 手动记录入口收敛与食物详情图片设计

## 目标

本次调整聚焦两个页面体验问题：

1. 手动记录页移除重复的页面标题和标准食物库入口卡片，减少用户从食物库进入后的重复信息。
2. 将已有的食物主图放入食物详情页，建立“名称与营养优先、图片辅助识别”的详情结构。

本次不改变食物库数据、不新增图片生成、不新增图片上传，也不改变手动记录的保存接口。

## 范围

### 手动记录页

删除以下两个视觉区域：

- `补充这一餐` 页面标题；
- `从标准食物库添加` 入口卡片及其 USDA 说明。

保留以下功能：

- 从食物库返回后展示已选食物；
- 餐次名称、时间、餐次类型；
- 食用份量和营养输入；
- 保存并同步饮食记录。

### 食物详情页

采用 C 方案的层级顺序：

1. 食物名称、来源/分类和标签；
2. 横向食物图片；
3. 份量选择；
4. 营养成分；
5. 营养洞察；
6. 底部操作按钮。

图片组件使用现有 `FoodThumbnail`，详情页传入 `prefer="detail"`，优先取：

1. `food.image.detailUrl`；
2. `food.image.listUrl`；
3. `food.image.thumbnailUrl`；
4. 分类图标占位。

图片必须继续经过现有可信域名校验和加载失败回退逻辑。没有图片或图片加载失败时，页面仍保持可用，不显示破损图片图标。

## 数据与接口

不新增后端接口和数据库字段。现有食物详情数据已经包含图片对象，前端只调整详情页的图片偏好和布局位置。

不改变食物版本切换、营养计算、手动记录选择和返回流程。

## 视觉约束

- 图片作为辅助视觉，不放在食物名称之前；
- 采用横向容器，圆角与当前详情页卡片保持一致；
- 保持现有北欧自然、低饱和色彩和分类占位图风格；
- 不增加图片标题、版权说明、图片切换控件或额外操作按钮；
- 删除区域后，详情内容自然上移，不留下空白占位。

## 验收标准

### 手动记录页

- 页面不再显示“补充这一餐”；
- 页面不再显示“从标准食物库添加”入口卡片；
- 从食物库选择食物后，已选食物、份量、营养和保存流程正常；
- 未选择食物时，仍可手动填写并保存。

### 食物详情页

- 有已审核图片时显示详情图，且位于名称/标签之后；
- 无图片时显示分类图标占位；
- 图片加载失败时自动回退，不影响营养信息和底部按钮；
- 份量切换和营养计算结果不变；
- 食物版本切换后图片随当前版本更新。

### 验证

- 运行相关单元测试；
- 运行 TypeScript 检查；
- 构建微信小程序并执行 WXSS 兼容性检查；
- 检查工作区无格式错误。

## 非目标

- 不批量生成或重新审核食物图片；
- 不修改数据库图片记录；
- 不改动食物库列表页；
- 不新增图片上传、图库浏览和多图切换；
- 不改变主环境数据库权限和生图 Worker 配置。
