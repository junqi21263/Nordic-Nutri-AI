# 成就解锁弹窗与动画设计

## 范围

本阶段不改造成就列表、核心成就定义或数据库结构。只改造两类现有成就交互：

1. 用户本次新解锁成就时的庆祝弹窗与轻量动画；
2. 点击未解锁成就时的进度说明弹窗。

现有成就数据、云端刷新和页面入口保持不变。

## 解锁庆祝弹窗

### 触发

- 成就刷新结果中出现相对于本地已见集合的新解锁项时，产出 `achievementUnlocked` 事件；
- 首次加载时仅同步已见集合，不触发；
- 事件按顺序排队展示，避免多个成就重叠；
- 弹窗关闭或完成主操作后再展示下一枚。

### 内容

- 文案：`成就已解锁`、成就名称、成就描述/条件完成说明；
- 绿色勾选或既有成就图标；
- 成长进度（已解锁数量 / 成就总数）；
- 主按钮：`继续记录`，关闭弹窗并回到当前页面；
- 次级文字操作：`查看成长里程`，关闭弹窗并前往现有成就页。

### 动画

- 弹窗以 280–360ms 的淡入、上移、轻微回弹进入；
- 图标使用柔和绿色光晕；
- 使用少量森林绿、鼠尾草绿、米白色叶片/圆点粒子短暂散开；
- 遵循小程序性能边界：纯 CSS transform/opacity，无 Canvas、无外部动画库；
- 动画是增强效果，关闭操作始终立即可用。

## 未解锁成就说明弹窗

- 保留当前底部弹层入口；
- 顶部使用锁图标、名称和“尚未解锁”；
- 显示唯一完成条件与当前进度/目标；
- 提供与条件对应的行动按钮：有饮食进度时为“去记录下一餐”，否则为“去记录第一餐”；
- 已解锁成就沿用同一弹层，显示绿色状态与完成日期，不播放庆祝动画。

## 组件与事件边界

- `achievement-store` 从 toast 回调演进为可订阅的解锁事件队列；
- App 根层渲染 `AchievementUnlockOverlay`，确保首页、记录页、教练页等任何刷新来源都可以安全展示；
- `AchievementDetailSheet` 只负责手动点击后的详情与行动，不处理自动庆祝；
- `achievementUnlocked` 事件至少携带 achievement ID，UI 从现有 achievement 状态读取名称、图标和进度；
- 旧 toast 不与新弹窗同时展示。

## 验收

1. 首次同步历史成就不显示庆祝弹窗。
2. 新解锁成就按队列依次显示一次；事件包含 achievement ID。
3. 解锁弹窗包含名称、完成说明、成长进度、继续记录和查看成长里程。
4. 未解锁详情显示锁、条件、进度与去记录按钮。
5. 已解锁详情显示完成日期，不触发庆祝。
6. 现有成就刷新与页面入口不回归；小程序类型检查、单元测试、构建和 WXSS 校验通过。
