# 保存本餐成功接入设计

## 目标

把已确认的“保存本餐成功”中文庆祝弹窗接入真实餐食创建流程。手动记录、拍照识别结果保存，以及份量调整中新建餐食均在服务端保存成功并同步本地数据后显示同一弹窗。移除开发预览入口。

## 范围与非范围

- 范围：新建餐食成功后的统一弹窗、中文文案、按钮导航、本地状态同步、开发预览清理。
- 非范围：修改服务端餐食 API、改变既有编辑餐食成功后的导航、重设计庆祝卡片视觉、上传或发布小程序。

## 架构

新增一个短生命周期的 Zustand 保存庆祝状态，保存刚创建餐食的 ID、名称、热量和宏量营养素，以及保存前后的当日热量。任一创建链路先调用现有 `createProductMeal`，再使用其返回餐食和 `getProductMeals` 刷新现有 `meal-store`，最后设置庆祝状态。

`PageLayout` 在页面层统一渲染 `MealSavedCelebration`。这样弹窗覆盖发起保存的页面，而不需要每个页面各自复制动效、中文文案和按钮状态。关闭弹窗仅清除本地庆祝状态，不再次调用保存接口。

## 按钮与导航

- 主按钮为“查看本餐”：清除庆祝状态，使用刚保存餐食 ID 跳转 `/pages/meal-detail/index?id=<id>`。
- 次按钮为“继续记录”：清除庆祝状态，使用 `Taro.switchTab` 返回首页；首页和记录页由已同步的 `meal-store` 立即读取最新餐食。
- 保存失败、返回空餐食或同步失败时不触发庆祝弹窗，保持既有错误提示和恢复路径。

## 数据同步

保存前从当前 `meal-store` 计算当天热量，作为进度条起点。保存成功后以 `getProductMeals` 的远端结果更新 `meal-store`，并从已保存餐食及同步后的当天餐食计算弹窗终点和营养数据。这样手动和拍照流程显示同一真实数据，而不是页面临时输入值。

## 清理

删除 `pages/meal-saved-preview`，从 `app.config.ts` 移除开发条件路由，并移除只服务预览页的样式与测试断言。保留独立庆祝组件、动画工具与真实流程的行为测试。

## 验收

1. 手动记录保存后只写入一次，状态同步完成后出现中文庆祝弹窗。
2. 拍照识别结果直接保存和份量调整后新建保存都出现同一弹窗。
3. “查看本餐”进入刚保存的详情；“继续记录”回到首页。
4. 首页与记录页可读取刚保存的餐食，进度从保存前动画到同步后的当天总量。
5. 生产与开发构建中均不再存在预览路由或“Replay Animation”入口。
