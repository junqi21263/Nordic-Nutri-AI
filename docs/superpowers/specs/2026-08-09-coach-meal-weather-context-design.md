# NOVA 餐次状态与天气提示设计

## 目标

NOVA 教练首卡在用户保存餐食后，立即依据早餐、午餐、晚餐的真实记录状态和营养进度更新唯一主行动；天气作为可选的一行辅助提示出现，不增加卡片、不抢占营养行动、不拉长首屏。

## 首卡信息层级

1. 问候语：沿用共享的短问候规则。
2. 当前状态：用一句话说明今天已记录及缺失的餐次。
3. 今日行动：只显示一个营养或记录行动。
4. CTA：与今日行动一致。
5. 天气提示：仅在命中安全相关天气规则时显示一行。

天气不得替代餐次记录或营养缺口的主行动。

## 餐次状态规则

餐次以当天已保存的 `breakfast`、`lunch`、`dinner` 类型记录判断，不以总餐数替代。

| 记录状态 | 当前状态 | 今日行动 | CTA |
| --- | --- | --- | --- |
| 三餐均未记录 | 今天还没有餐次记录 | 今天先完成第一餐记录 | 记录第一餐 |
| 已早餐，未午餐 | 早餐已记录 | 午餐还没记录，按自己的节奏补上 | 记录午餐 |
| 已早餐、午餐，未晚餐 | 已完成两餐记录 | 晚餐还差一餐，继续完成今天节奏 | 记录晚餐 |
| 已午餐，早餐缺失 | 午餐已记录 | 早餐可按需补记 | 补记早餐 |
| 晚间仍未午餐且未晚餐 | 今天还有餐次未记录 | 可补记午餐，或直接安排晚餐 | 记录晚餐 |
| 三餐均已记录 | 三餐已记录 | 根据营养完成度给出下一步 | 查看今日进度 |

三餐均已记录后：

- 蛋白质明显不足时，行动为补足优质蛋白；
- 热量明显偏低时，行动为补足主食与蛋白；
- 目标完成良好时，行动为保持节奏；
- 不再显示“记录下一餐”或强制加餐。

## 时间规则

- 当前餐次为早餐、午餐或晚餐时，优先引导记录该餐。
- 若当前时间已明显越过缺失餐次，则使用“补记”措辞，不制造催促感。
- 晚间未记录午餐与晚餐时，CTA 指向记录晚餐；主文案可提示午餐可补记。

## 天气提示

天气提示位于“今日行动”下方，最多一行，低视觉权重。仅展示如下命中项之一：

| 条件 | 单行提示 |
| --- | --- |
| 高温或体感偏热 | `☀️ 体感偏热，外出记得分次补水。` |
| 强降雨或雷暴 | `☔ 有降雨，出门记得带伞。` |
| 低温 | `❄️ 天气偏冷，注意保暖和规律进餐。` |
| 大风或沙尘 | `🌬️ 风力较大，外出注意防风。` |
| 普通天气或数据不可用 | 不显示天气提示位 |

一期不输出训练强度建议。高温提醒仅限补水、避晒和户外舒适性建议，不做医疗或训练指导。

## 授权、数据与缓存

1. 用户首次看到天气提示位时显示轻量入口 `开启天气提醒`。
2. 只有点击入口后才请求微信当前位置授权。
3. 授权成功后，通过当前位置获取当前天气并在本地缓存 30 分钟。
4. 教练页下拉刷新时，主动刷新天气；常规重进页面优先复用缓存。
5. 拒绝授权、定位失败或天气接口失败时，隐藏天气行，不影响首卡的餐次与营养建议。
6. 后续在“我的”页提供天气提醒开关；关闭时清除缓存并停止定位请求。

## 更新链路

```text
餐食保存成功
→ 更新本地与远端当天餐食
→ 重新计算早餐/午餐/晚餐状态和营养完成度
→ 刷新 NOVA 今日行动、CTA、今日进度、快捷提问
→ 保留或刷新天气辅助提示（不阻塞以上更新）
```

## 验收条件

1. 保存早餐后，首卡不再显示“记录第一餐”，而显示午餐相关行动。
2. 保存午餐后，首卡优先显示晚餐相关行动；早餐缺失时采用“补记早餐”。
3. 三餐均保存后，首卡 CTA 变为“查看今日进度”，并基于营养缺口给出行动。
4. 高温、雨天、低温与大风分别展示对应单行提示；普通天气不占位。
5. 首次未授权不弹系统定位框；仅点击“开启天气提醒”后请求授权。
6. 定位或天气失败时，营养首卡仍正常更新。
7. 首卡布局维持现有高度，不新增天气卡片。
