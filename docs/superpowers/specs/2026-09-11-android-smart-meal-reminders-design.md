# Android 智能记录提醒（P0-3）设计稿

## 目标

首期只覆盖 Android APK，为用户提供低频、可关闭、无压力的餐次记录提醒。提醒只服务于用户主动开启的餐次，不做 AI 行为判断、GPS 触发或强制打卡。

## 范围与约束

- 覆盖早餐、午餐、晚餐；加餐首期不加入提醒。
- 默认时间窗口：早餐 07:00–10:00、午餐 11:00–14:00、晚餐 17:00–21:00。
- 用户可在对应窗口内选择具体提醒时间，并可分别关闭任意餐次。
- 每个餐次每天最多触发一次。
- 当天对应餐次已有记录时，不创建该餐次的提醒；记录保存后取消当天尚未送达的提醒。
- 退出登录时取消当前设备上的全部提醒；再次登录后按该账号的本地设置重建。
- 不改微信小程序提醒逻辑；不实现高频 Push、AI 自动判断、GPS、精确行为预测或连续打卡强提醒。

## 方案选择

### 推荐：Android 本地通知

使用与当前 Capacitor 主版本匹配的 Local Notifications 插件。提醒由系统调度，App 被关闭时仍可触发；前端只负责设置、取消、重建和根据餐食记录生成通知内容。

### 不采用：前台检查

只在打开或回到 App 时检查会漏掉 App 关闭期间的提醒，不满足首期体验。

### 不采用：服务端 Push

需要设备令牌、服务端调度和更多权限治理，当前低频本地提醒不需要这套复杂度。

## 用户体验

入口：`我的 → 饮食管理 → 记录提醒`。

页面包含：

1. 总开关“记录提醒”（这是本地系统通知开关，不接入服务端 Push）；关闭后取消三餐全部提醒。
2. 早餐、午餐、晚餐三行，每行显示开关、当前时间和允许范围。
3. 点击时间进入 Android 时间选择器，只允许选择对应范围内的时间。
4. 首次打开总开关或任一餐次开关时请求系统通知权限；用户拒绝时保持关闭，并用统一反馈弹窗说明可在系统设置中开启。
5. 页面保存采用即时生效，切换开关或时间后立即重建本地计划，并显示短反馈。

通知文案按以下优先级选择：

- 最近多天未记录：`最近有点忙？\n不用补齐，从这一餐重新开始就好。`
- 近期保持连续记录：`今天也记一下这一餐 🌿\n你的记录节奏正在慢慢形成。`
- 普通情况：`午餐还没记录吗？\n拍一下就好 📷`

通知点击打开记录页，并预选对应餐次；不自动创建餐食。

## 数据与状态

新增按账号隔离的 Android 本地提醒设置，建议结构：

```text
SmartReminderSettings {
  enabled: boolean
  meals: {
    breakfast: { enabled: boolean, time: "HH:mm" }
    lunch: { enabled: boolean, time: "HH:mm" }
    dinner: { enabled: boolean, time: "HH:mm" }
  }
}
```

默认时间使用窗口中间值：早餐 08:30、午餐 12:30、晚餐 19:00。该默认值可在实现阶段根据产品确认调整；用户自定义时间必须落在对应窗口内。

设置存储在当前 Android 设备并以账号 ID 隔离，避免退出后串用其他账号；现有云端 `notification` 字段继续作为兼容的总开关来源，但餐次时间和独立开关首期不扩展后端模型。

## 调度与判断

统一的提醒协调器负责：

- 读取当前账号设置和当天餐食记录。
- 生成当天尚未记录且已开启餐次的计划。
- 为每个餐次使用稳定通知 ID，避免重复排程。
- 保存餐食后取消对应餐次当天通知。
- App 启动、回到前台、设置变更、登录成功后取消旧计划并重建当天计划。
- 退出登录、账号注销时取消全部计划。

用户在某餐次设定时间之后才开启提醒时，首期不补发当日提醒，避免产生打扰；从下一个有效日期开始生效。当天已经送达的通知无法撤回，但回到 App 后会根据实际记录重建后续计划。

## 错误与权限处理

- 系统通知权限不可用或被拒绝：不创建计划，保留用户设置意图但将有效状态显示为关闭，并提供系统设置引导。
- 时间选择器返回越界值：前端校验并回退到该餐次默认时间，不发送非法计划。
- 本地通知排程失败：不阻塞餐食记录；显示“提醒暂时未生效，请重试”，并在下次启动重试。
- 记录接口失败：不取消提醒，避免用户实际未记录却失去提醒。
- 账号切换：先取消旧账号通知，再加载新账号设置并重建，防止跨账号通知。

## 实现边界

- 新增 Android Local Notifications 依赖、权限配置和最小原生桥接配置。
- 新增提醒领域类型、时间窗口校验、文案选择和通知协调器。
- 新增 Android 记录提醒设置页及个人中心入口。
- 在餐食保存、登录、退出登录和 App 前后台生命周期接入重建/取消。
- 不修改微信登录、微信小程序页面和服务端 Push。

## 验证

- 单元测试：时间窗口校验、通知 ID 稳定性、已记录跳过、关闭餐次跳过、文案优先级、账号隔离。
- 页面测试：入口、总开关、三餐独立开关、时间选择、权限失败反馈。
- Android 构建：Taro Android H5 构建、Capacitor 同步、Gradle Debug APK 构建。
- 设备检查：安装到当前无线调试设备，确认权限请求、开启/关闭、通知点击路由和已记录自动跳过；不宣称未实际点击验证的结果。
